# Website

The product site, <https://galexander77.github.io/openframe/>, lives in
`openframe-website/`: a static Astro site with its own package, lockfile
and scripts ([[ADR-076 The website is a static Astro site that reads docs at build time]]).
Its README says how to develop, build, capture screenshots and deploy; this
page says what the site is for, how it stays true to the app, and what to
check before any media lands in the repository.

## What it is

- **Home:** the launch film in a player over the film's own timeline
  (chapters on a picture track, the music's sections below, drawn at their
  measured loudness, and a playhead), what OpenFrame is in one line, six
  feature sections with a looping product clip each, the AI story, the
  experiment, local-first privacy, building from source and open source.
- **Features:** every group from [[Features]] (editing, color, titles and
  kinetic type, captions, effects and transitions, audio and loudness, AI
  tools, export and deliverables, MCP for agents) with a clip or a
  screenshot, and the smaller capabilities after them.
- **AI and MCP:** the three ways AI is used (agents over MCP, the AI
  assistant, headless render), how to connect Claude Code and Codex (the
  Connect agents tab's buttons, or the commands from [[Automation]]), what
  agents can do by tool group, and the safety model.
- **How it was built:** the experiment: who did what (agents, mostly Claude
  Opus 5.5 in Claude Code, with Codex; the owner steering), how agents
  work on the project, the build log from [[History]], how the films were
  made by agents, and what the project is not yet.
- **Docs:** getting started (build from source), and, rendered from this
  folder at build time, the [[User guide]], [[Keyboard shortcuts]], the
  [[MCP tools]] reference (with a search island), the [[Agent playbook]]
  and [[Architecture]]; contributing summarizes CONTRIBUTING.md.
- **Privacy** (what the app and the site connect to, and how that was
  checked) and **Credits** (the footage, the music, the open-source
  projects).

## How it stays true to the app

- **The docs are read at build time,** from `../docs` or `OPENFRAME_DOCS`;
  nothing in `docs/` is copied into the site. `docs/MCP tools.md` and
  `docs/Agent playbook.md` are generated by the app from its tool
  definitions (`npm test` fails when they drift), so the site's tool
  reference is the app's. A docs change on `main` redeploys the site.
- **Numbers are parsed, not typed:** the tool count, the tool groups, the
  number of decision records, the effect, transition, look, blend-mode,
  template and word-art counts from [[Features]], and the first day of the
  [[History]]. If a pattern stops matching, the sentence drops the number
  instead of showing a wrong one.
- **Hand-written pages name their sources.** The home, features, AI,
  experiment and privacy pages are prose: each claim comes from
  [[Features]], [[Automation]], [[User guide]], [[Roadmap]],
  [[Release preparation]], [[History]] or the code, and has to be changed
  with them. The feature groups and their icons and hues are in
  `openframe-website/src/lib/features.ts`; the build-from-source commands
  (the README's and CONTRIBUTING.md's) in `src/data/build.ts`.
- **What it does not claim:** no download or release date (there is no
  packaged release; users build from source), no platform it has not been
  tested on (the desktop app on Windows, the web build in Edge), no model
  name of anyone's machine, and no number nobody measured.
- **Icons are the app's.** `scripts/copy-icons.mjs` copies the app's Lucide
  set into `src/icons/`; a feature uses the icon the app shows for it (the
  library tab or the toolbar button) and the same hue on every page.

## Media

- **The launch film:** `public/media/launch-film.mp4`, the 68-second
  voiced film from [[Launch film 3 through MCP 2026-10-19]]: H.264 1080p30
  at 1.75 Mbit/s (two-pass), the master's own AAC track copied as it is
  (192 kbit/s, -14.2 LUFS, -1.0 dBTP), `+faststart`, 16.6 MB, from the
  82 MB master. Re-encoding that AAC at 128 kbit/s kept the loudness but
  raised the true peak to -0.7 dBTP, so `make-media.mjs` copies an AAC
  track and encodes only anything else.
- **Its captions** (`launch-film.en.vtt`) are the narration, converted by
  `make-media.mjs --captions` from the SRT the export wrote. The page's
  transcript reads the same file and adds what is on screen in each
  chapter, so captions and transcript cannot drift.
- **The music lane's loudness** is the score's, before it was ducked under
  the voice. The film's mix flattens the sections (the narration runs
  through all of them), and the score is not kept beside the film. But
  generate_music is deterministic
  ([[ADR-085 Music is composed and synthesized in the app, seeded and offline]]):
  bundling the app's `src/lib/music` for Node and rendering the film's own arguments
  and seed gave the same master report as the film (gain, limiting,
  -14.02 LUFS), and ffmpeg's ebur128 measured that render section by
  section. `src/data/film.ts` says how.
- **Loops:** nine 5-to-8-second muted clips, 1280x720, VP9 WebM and H.264
  MP4, 0.14 to 1.5 MB each, cut from the agents' 2560x1440 recordings and
  cropped to the feature. They load and play only while on screen, have a
  pause button, and wait to be played under reduced motion.
- **Screenshots:** `src/assets/screens/*.webp` from `scripts/capture.mjs`
  (near-lossless WebP at 2x); Astro serves AVIF and WebP at several widths.
- **Full-range video fails in Edge.** The recordings are full-range (JPEG)
  YUV, as the browser's screencast writes them. VP9 encoded from them
  played in nothing on Edge for Windows: `PIPELINE_ERROR_DECODE` on the
  first frame, while the H.264 copies played. `make-media.mjs` converts to
  limited range and tags BT.709, after which every loop decodes.

## Privacy checklist for media

The repository is public. Before committing any image, video or capture:

1. **Look at every frame.** For a video, a contact sheet of at least two
   frames a second (`ffmpeg -vf "fps=2,scale=640:-1,tile=3x6"`); for a
   screenshot, the image itself at full size.
2. **No personal data:** no user names but the public GitHub handle in the
   repository URL, no email, no machine paths, hostnames or Windows user
   folders, no project or file names from someone's own work, no local AI
   model names (the assistant lists the machine's installed models: stub
   `**/api/tags` to `{"models":[{"name":"llama3.1:8b"}]}`, as
   `capture.mjs` does), no tokens (the Connect agents tab shows the MCP
   token behind a reveal button: never reveal it on camera).
3. **Only shareable footage:** the CC0 and public-domain clips on the
   Credits page, or media made for the project.
4. **Strip metadata:** `-map_metadata -1 -fflags +bitexact` for video
   (no creation time or encoder path); sharp writes images without EXIF.
5. **Scan the staged diff** for paths, names and secrets before the commit.

## Deploy

`.github/workflows/pages.yml` builds the site and deploys it with
`actions/deploy-pages` on pushes to `main` that change `openframe-website/`,
`docs/` or the workflow, or by hand. It is the repository's only
deployment, and it does nothing until the owner pushes and sets Settings >
Pages > Source to "GitHub Actions"
([[ADR-077 The website deploys to GitHub Pages from main]]). On a project
site `robots.txt` is not at the host's root, so search engines need the
sitemap (`/openframe/sitemap-index.xml`) submitted by hand.

## Local notes

- The dev server uses port 1447; the app's own servers use 1420 and up.
- `openframe-website/dist/` and `.cache/` are git-ignored. While the app
  still sits at the repository root, a built `dist/` is inside the app's
  Vite root; delete it if the app's dev server ever scans it.
