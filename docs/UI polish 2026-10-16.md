# UI polish 2026-10-16

The owner reported that the main track's speaker (mute) toggle was cut off at
the right edge of the timeline's track header, in a desktop window of about
2026×1084 CSS px, and asked for a look across the whole application. This
pass audited every surface at three window sizes and at the splitters'
extremes, fixed what was broken without changing any feature, and records
*why* each problem happened, so the same mistakes are not made again.

## Method

- Branch `ui-polish` (worktree `<worktrees>\video-editor\ui-polish`),
  rebased onto `main` at `8d1c03b`. Web build served by its own Vite on :1440.
- Headless Edge through playwright-core. Viewports **2026×1084** (the
  owner's window), **1600×950** and **1280×720**, plus two splitter layouts:
  narrow side panels (library 240 px, inspector 260 px, the splitters'
  minimums) and wide side panels (library 640, inspector 560), which squeeze
  the player to its 320 px minimum.
- One project with every kind of content: video with and without sound, a
  0.15 s image and a 0.1 s text (very short clips), a photo overlay, a
  title, a sticker, an adjustment layer, two audio tracks, three captions
  (one 0.1 s long), four markers, a transition, four effects, a speed curve
  and keyframes, built with `window.videoEditor.exec`.
- Surfaces: Home (cards, menu, search, empty state); every title-bar menu;
  every library tab, the grid and list views, category navigation, Manage
  media with folders, the source monitor; the player header, transport,
  scopes and full screen; every inspector tab and sub-tab for video, audio,
  text, caption, sticker, image, adjustment and transition clips and for no
  selection, with effect presets, Paste attributes, the color sub-tabs, the
  speed-curve graph and the animation picker; the timeline toolbar, track
  headers in locked, hidden and muted states, clips at minimum, fit and
  maximum zoom, the volume line and fade knobs, markers, the keyframe panel,
  context menus, the tool menu and the marquee; the Export, Shortcuts, Save
  a copy and marker export dialogs, the Copilot panel, tooltips at the
  window edge and keyboard focus rings.
- Each screenshot was read at full size. Layout claims were measured with
  `getBoundingClientRect`; one-pixel details (focus ring edges) were checked
  on the pixels, because a downscaled preview hides them.
- Gate before every commit: `npx tsc --noEmit` and `npm test`. Drives run
  against :1440 after the rebase, all passing: timeline-menu, timeline-ux,
  marker-export, home-menus, keyframes, markers, effects-inspector,
  media-library, viewer-guides, align, voiceover and playback.

## Rules of thumb

- **Popups inherit their anchor's width limits.** An absolutely positioned
  menu shrink-to-fits inside its containing block; in a narrow anchor that
  is min-content. Give menus `width: max-content` and a `max-width`.
- **Clipping is per element, not per axis you meant.** `overflow: hidden`
  clips dropdowns and focus rings, and `overflow-x: auto` forces
  `overflow-y: auto`, which clips too. Use `overflow-x: clip` for a bar
  that must not spill sideways; take a popup out with `position: fixed`
  and `top/left: auto` (it stays where it would have been); inset focus
  rings inside scrollers.
- **Panels need `minmax(0, 1fr)` columns.** An implicit `auto` column grows
  to the widest row's min-content and drags every row past the panel edge.
- **Saved splitter sizes must give way to the window**, on both axes:
  `minmax(min, saved)`.
- **Splitter-sized panels want container queries, not media queries.**
  `container-type` adds layout containment, so a `position: fixed`
  descendant would be placed and clipped by the panel; check first. The
  inspector qualifies: EaseMenu is portaled to `body` and dialogs open in
  the top layer.
- **Class names are global.** Search before reusing one.
- **One constant, one place.** The header width lived in Timeline.tsx,
  timeline.css and two drives; drives read layout from the page.
- **Labels wrap:** `min-height`, not `height`, on buttons with text.
- **Derive counts from pixels**, such as grid lines from the graph's height,
  not from a constant.
- **Scroll-into-view must know about edge fades.**

## Found, not fixed

- **Align bar overflows the narrowest inspector.** The new align row under
  Transform (from the align work, which was off limits for this pass) is
  wider than a 260 px inspector: its last buttons are clipped at the panel
  edge. It could wrap or scroll.
- **Keyframe dock in a 720 px window.** The dock's 150 px minimum plus the
  38 px toolbar exceeds the 180 px timeline, so the dock covers every track
  and its bottom 8 px is cut. This needs a layout decision (an overlay dock
  or a smaller minimum), not a style change.
- **Effect parameter labels ellipsize** in effect cards: Mirror's "Axis (0
  horizontal, 1 vertical, 2 both)" shows as "Axis (0 horizon…", Zoom pulse's
  "Beats per second" as "Beats per seco…". Mirror's axis wants a segmented
  control; the labels are catalog content.
- **A chord typed in UI prose.** The keyframe panel's hint reads
  "Shift+click adds · drag moves · right-click for easing", against the
  house rule that chords come from the keymap. Not a layout problem; left
  for its owner.
- **Library tabs scroll even at 2026 px wide.** The library keeps a 470 px
  default whatever the window, so AI tools and Markers sit behind the right
  fade. This is CapCut's scrolling strip, kept by design.
- **No timecode and an off-center play button at the player's 320 px
  minimum.** The frame, play and loop buttons (136 px) and the ratio,
  quality and full-screen controls (140 px) leave no room for even the
  current time (75 px), so it hides and the button group sits about 58 px
  left of center. Hiding a control instead would remove a feature; the
  playhead's time is still on the timeline.
- Deliberate and left: Captions' "Export VTT" is a ghost button beside
  bordered ones (secondary action); transition and animation durations show
  read-only values instead of number fields (behavior, not styling).
- Not covered: native `<select>` popups (guides, ratio, quality, filters)
  draw outside the page in headless Edge; the source monitor's first frame
  was black in headless (decode timing, not styling); window-header.js
  needs the desktop host's arguments and does not run under run.mjs.
